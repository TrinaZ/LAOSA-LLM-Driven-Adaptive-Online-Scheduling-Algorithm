## 核心思想

工业信息物理系统（ICPS）中的调度问题存在一个根本矛盾：物理层持续发生非平稳变化（任务分布漂移、机器故障、目标重定义），但现有方法要么无法响应变化（静态规则），要么响应太慢（深度强化学习需要数千次交互重新训练），要么响应快但没有安全保证、也不知道自己何时会失败（现有LLM引导的启发式进化方法）。

LAOSA是一个四子系统闭环系统：**监测**变化发生、**诊断**变化类型、**生成**候选修复方案、**治理**部署安全性。核心贡献不是"用LLM生成调度规则"本身（这一点已有EoH、SeEvo等工作做过），而是两点：

1. 一个**被证明、不是靠经验观察出来的**安全保证——无论LLM生成了什么，部署的规则性能都不会劣于已知最优的静态兜底方案超过$(1+\tau)$倍。
2. 一套**测量协议**，用于在运行任何实验之前，判断生成式搜索对某个具体目标函数是否值得期待——而不是事后才发现某个目标"就是比较难"。

## 四子系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                      LAOSA 四子系统闭环                        │
│                                                               │
│   S1: 监测 (Monitor)          S2: 诊断 (Diagnose)             │
│   CUSUM统计过程控制      →     瓶颈定位 + 变化类型分类           │
│   O(log h)检测延迟              (distributional/structural/    │
│         │                        semantic)                    │
│         │                            │                        │
│         │                            ▼                        │
│   S4: 治理 (Govern)      ←    S3: 生成 (Generate)              │
│   分级部署 + 兜底证明            LLM引导迭代搜索                │
│   ρ ≤ (1+τ)ρ*                  (best-of-N, N=4)                │
│   与S3输出质量无关                                             │
└─────────────────────────────────────────────────────────────┘
```

- **$S_1$（监测）**：基于CUSUM的连续统计过程控制，误报率校准至1%，检测延迟$\mathcal{O}(\log h)$。
- **$S_2$（诊断）**：滑动窗口瓶颈定位，输出变化类型标签（分布型/结构型/语义型），这个标签直接决定$S_4$授予多少自主权。
- **$S_3$（生成）**：在一份文档化的算子词表$\mathcal{V}$上做LLM引导的best-of-N迭代搜索，沙盒编译验证候选方案。
- **$S_4$（治理）**：分级部署——分布型变化自动部署、结构型需要专家验证、语义型需要人工签字确认；若没有候选方案通过部署阈值，回退到已知最优静态规则，保证$\rho_{\mathrm{LAOSA}}\leq(1+\tau)\rho^*$，这个保证的证明**不依赖$S_3$输出的任何性质**。

## 部署边界理论

LLM引导的启发式进化不是普遍有效的，本项目形式化了两个决定其能否成功的边界：

- **算子边界**：用经典调度理论中的pairwise-interchange论证，测量一个目标函数的局部偏好结构能否被给定算子词表表达。这不是拍脑袋判断，而是一个可计算的统计量（候选枚举 + Kendall's $\kappa$）。
- **架构边界**：某些目标函数（如涉及Gini系数的公平性目标）的最优规则本质上无法分解为逐任务打分，这类目标函数无论词表多丰富、搜索预算多大，都存在一个恒定的性能差距。

两个边界共同支撑了两项**部署前**（不用真的跑实验）就能做的检查：算子覆盖度检查、逐任务可表达性检查。

## 已知问题（如实披露）

这个项目经历过一轮系统性的代码与数据审计，发现并修复了若干问题，也有一些问题仍未解决。如实列在这里，而不是等审稿人或复现者自己发现：

- **已修复**：五目标spectrum实验中，Fairness/Energy两个目标的评分归一化存在单位不匹配和符号反转两个bug，曾导致真实的LLM搜索活动被错误地判定为"0次查询"。已定位、修复、重新运行。
- **已修复**：WGS/Fab主表的统计显著性检验早期存在伪重复问题（把每个场景下多个起始基线条件当作独立观测），已改为按场景×种子聚类计算。
- **未解决**：`transfer_4seeds_raw.json`中40%的记录带有`'description'`字段报错，根因尚未定位；受此影响，两条域内对照路径（Cloud→Cloud、Semiconductor→Semiconductor）目前没有任何有效试验数据。
- **未解决（较严重）**：6条cross-domain transfer路径中有3条被发现存在伪重复——名义上的4个随机种子实际产生了完全相同的逐条结果，说明种子参数未能为这几条路径引入真正的独立随机性。相应的统计显著性结论已在论文中撤回，恢复这一结论需要先定位根因、验证种子独立性、重新运行实验。
- **反向验证通过**：用同一套方法论（伪重复检测、静默空转搜索检测）反查了WGS/Fab两张主表，均未发现类似问题。
